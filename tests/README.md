# Standalone verification

Run `npm run verify` from the repository root after `npm ci --prefix ui`. It runs the portable Node regressions, TypeScript checking and the production UI build, then the Java 17-compatible connection, completion and update-policy checks. No root npm dependencies are required. Native Android build, lint and emulator tests run separately through Gradle and GitHub Actions.

The Node tests preserve the Android model, session details and live status, family grouping, native-message state and limit-display coverage from the source project. Grouping expectations are explicit fixtures instead of importing the desktop renderer. Limits use normalized Hub response fixtures instead of importing the production aggregator or Ollama parser.

`upstream86.test.js` covers OpenDesign workspace identity, wallet display, quota history calculations, missing versus zero readings, cycle bounds, source conflicts, snapshot checksums and history-message isolation. The portable history model is taken from the pinned upstream commit with only its CommonJS import rebased. `LimitsHistoryStoreTest` separately exercises the Android SQLite implementation; `StartupTest` checks packaged history scripts and the actual WebView preview. These tests do not require provider credentials or live provider APIs.

`upstream87.test.js` consumes normalized MiniMax fixtures (`upstream87Limits.json`) shaped after upstream Code points, quota and API billing output. It checks independent identities/units/status, confirmed same-region heading groups, unknown versus zero cash Spend, unlimited/Video semantics, monthly full-stats compatibility and browser loading of the unchanged upstream `windowText.js`. It does not bundle or run the MiniMax OAuth/API collector. Native regressions add MiniMax history isolation, Video cycle bounds, widget labels and actual WebView rendering; successful compilation alone does not establish native acceptance.

`upstream88.test.js` covers Gemini CLI, Mistral Vibe, Prime Agent and Jcode names and session accounting; Mistral API/Vibe money versus percentage-only allowances and the independent wallet; anonymous device boundaries; and MiMo product labels and zero/unknown balance details. The data is synthetic normalized Hub output, not live provider parsing. `LimitsHistoryPolicyChecks` exercises compatible takeovers, observer preference and legacy conflicts as pure Java; `LimitsHistoryStoreTest` separately checks daily totals and persisted guard values across SQLite reopenings. `StartupTest` adds packaged-catalog, tool-filter and actual WebView quota/detail cases. Desktop plugin quota records, including OpenAI API credits, are absent from the current Hub wire contract and are outside these tests.

`upstream90.test.js` covers the v0.89/v0.90 consumer changes: main-session `latestModel` snapshots and unknown clears, model-search/group accounting, Hark raw counts and unmetered top-up, independent Qoder credit pools, measured input cache efficiency, completed/zero-hit session detail, lifetime active-day completeness, and the updated shared conflict-span calculation. The fixtures are normalized synthetic Hub output; these tests do not run provider collectors. Native additions cover WebView rendering and SQLite Qoder/Hark stream isolation after reopening. Emulator/device execution is still a separate acceptance gate; a compiled instrumentation APK is not a passing runtime result.

The authenticated real-Node-Hub integration cases from `model.test.js`, `upstreamLimits.test.js`, `upstream84.test.js` and `upstream85.test.js` remain in the original source workspace described in [UPSTREAM.md](../docs/UPSTREAM.md). This repository does not bundle a Hub, provider parser or Electron app merely to run them. `upstream84Limits.json` contains normalized output from the source project's synthetic Muse/Manus fixtures. The portable tests exercise the Android consumer, tool filtering, device provenance, reasoning effort and model components; they do not claim to verify Hub authentication or provider parsing. Native authenticated GET requests, Keystore, completion notifications and widget rendering are covered by `app/src/androidTest/`; the startup suite also verifies v0.84/v0.85 rendering and interactions. Run `sh ./gradlew connectedDebugAndroidTest` on a dedicated emulator or device. Browser or Node tests do not replace native device acceptance.
